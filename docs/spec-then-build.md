# 從需求到專案：先規格後動手

> 在請 AI 寫程式之前，先用一頁文字寫下功能、輸入輸出、邊界條件與驗收方式，讓每次生成都有可判斷的依據。

## 學習目標

完成本單元後，你能夠：

1. 用固定格式寫出一頁式規格（spec），涵蓋功能、輸入輸出、邊界與驗收。
2. 把規格拆成數個可獨立執行與驗收的小任務。
3. 用規格驅動 AI，逐項確認完成，而不是整包丟給 AI 猜。

## 前置知識

- 先完成 [提示詞入門：把話說清楚](./prompt-basics.md)。
- 你能寫出包含目標、輸入、輸出、限制、範例的提示詞。

## 為什麼重要

沒有規格，AI 每產生一次版本，你只能憑感覺說「好像怪怪的」，改來改去沒有終點。有規格，你就能回答三個問題：要做什麼？怎樣算做完？怎樣算沒做對？這讓 AI 變成可靠的施工者，而你成為定義需求的人。規格也是你和 AI 之間唯一的「事實來源」，對話再長都不會走鐘。

## 核心內容

### 一頁式規格模板

把以下內容存成 `SPEC.md`，放在專案資料夾根目錄：

```text
# 專案：<名稱>

## 目的
<一句話說明這個工具為誰解決什麼問題>

## 功能
1. <功能一>
2. <功能二>

## 輸入
- 來源：<命令列參數 / 標準輸入 / 檔案>
- 格式：<純文字 / CSV / 每行一筆>

## 輸出
- 位置：<終端機 / 輸出檔>
- 格式：<欄位與範例>

## 邊界條件
- <空輸入時如何處理>
- <格式錯誤時如何處理>

## 驗收方式
- [ ] <可執行的檢查一>
- [ ] <可執行的檢查二>

## 不做的事（Non-goals）
- <明確排除的功能>
```

「不做的事」很重要：它防止 AI 自作主張加上你沒要的功能。

### 實例：單字計數工具

```text
# 專案：wordcount

## 目的
快速統計一個文字檔的單字次數，幫助檢查文章用字。

## 功能
1. 讀取指定文字檔。
2. 統計每個單字出現次數（不分大小寫）。
3. 印出總單字數與出現最多次的前 3 名。

## 輸入
- 來源：命令列參數，第一個參數為檔案路徑
- 格式：UTF-8 純文字

## 輸出
- 位置：終端機
- 格式：
  總單字數：N
  前 3 名：
  1. word (count)

## 邊界條件
- 檔案不存在：印出錯誤訊息並以離開碼 1 結束
- 檔案為空：總單字數為 0，不印排名

## 驗收方式
- [ ] `python wordcount.py sample.txt` 印出正確總數
- [ ] 對不存在的檔案，離開碼為 1
- [ ] 大小寫不同的同一單字被合併計算

## 不做的事
- 不支援一次處理多個檔案
- 不做詞形還原（running 與 run 視為不同單字）
```

### 把規格拆成任務

規格是目標，任務是路徑。把上面的規格拆成四步，每一步都能單獨執行驗收：

1. 讀取檔案並印出總行數（先確認讀檔正確）。
2. 依空白切出單字並轉小寫，印出總單字數。
3. 用字典統計次數，印出前 3 名。
4. 處理檔案不存在與空檔案兩種邊界。

每一步都請 AI「只做這一步」，你執行驗收後再進下一步。這比一次生成整支程式容易除錯。

### 用規格下提示詞

把規格片段貼進提示詞，AI 的產出會大幅收斂：

> 以下是規格片段：
> 功能：依空白切出單字、轉小寫、統計次數，印出總單字數與前 3 名。
> 限制：只用 Python 標準函式庫，輸出格式必須是「1. word (count)」。
> 請只實作這一步，並附一個可直接執行的測試資料。

對應的參考實作：

```python
# wordcount.py
import sys
from collections import Counter

if len(sys.argv) < 2:
    print("用法：python wordcount.py <檔案路徑>")
    sys.exit(1)

try:
    with open(sys.argv[1], encoding="utf-8") as f:
        words = f.read().split()
except FileNotFoundError:
    print(f"找不到檔案：{sys.argv[1]}")
    sys.exit(1)

counter = Counter(w.lower() for w in words)
print(f"總單字數：{len(words)}")
if counter:
    print("前 3 名：")
    for i, (word, count) in enumerate(counter.most_common(3), start=1):
        print(f"{i}. {word} ({count})")
```

準備測試資料 `sample.txt`：

```text
The cat and the dog
The CAT runs
```

執行與預期輸出：

```text
python wordcount.py sample.txt
總單字數：7
前 3 名：
1. the (3)
2. cat (2)
3. and (1)
```

## 常見坑

| 錯誤 | 原因 | 正確做法 |
|---|---|---|
| 跳過規格直接寫程式 | 覺得寫規格很慢 | 先花 5 分鐘寫規格，省下數輪來回 |
| 規格寫成「功能清單」 | 缺少輸入輸出與邊界 | 補上輸入、輸出、邊界、驗收 |
| 沒寫 non-goals | AI 自由發揮加功能 | 明確列出不做的事 |
| 一次把整份規格丟給 AI | 生成範圍過大難以驗收 | 依任務逐步生成、逐步驗收 |
| 驗收寫成「看起來正常」 | 無法客觀判斷 | 寫成可執行的指令與預期結果 |

## 動手練

**練習**：為「把 CSV 檔某一直欄印出來」寫一份一頁式規格，存成 `SPEC.md`，內容需包含至少兩項功能、輸入輸出格式、兩個邊界條件、兩項驗收方式與一項 non-goal。接著把它拆成三個任務，只完成第一個任務（讀檔並印出所有列數）並實際執行。

**提示**：邊界條件的靈感來源是「最奇怪但可能發生的輸入」，例如空檔、只有表頭、欄位數不一致。若 AI 幫你寫的規格太籠統，請它把每個驗收條件改寫成可執行的指令。

## 完成檢核標準

- [ ] 我寫出一份 `SPEC.md`，含功能、輸入、輸出、邊界、驗收、non-goals。
- [ ] 我把規格拆成至少三個可獨立驗收的任務。
- [ ] 我完成第一個任務並實際執行通過。
- [ ] 我能指出規格中哪一行對應到哪一項驗收。
- [ ] 我的驗收條件是可用指令驗證的，不是主觀描述。
